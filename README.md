# AI-черновик карточки товара (КИПиА)

Прототип сервиса: на вход — JSON о контрольно-измерительном приборе, на выход — черновик карточки для контент-менеджера B2B-магазина (SEO, характеристики, поисковые запросы, commercial-блок).

Модель **не имеет права выдумывать** технические характеристики. Если значения нет во входе, в результате будет пометка «данных нет».

## Стек

- Python 3.11+
- FastAPI + Uvicorn
- LLM через OpenAI-compatible API (OpenAI, Groq, OpenRouter или локальная модель)

## Установка и запуск

```bash
py -3 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

В `.env` укажите ключ и, при необходимости, другой endpoint:

```
LLM_API_KEY=sk-...
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini
```

Запуск:

```bash
uvicorn app.main:app --reload
```

Откройте http://127.0.0.1:8000 — веб-форма с примером первого товара.

API:

```bash
curl -X POST http://127.0.0.1:8000/generate -H "Content-Type: application/json" --data @samples/product_1.json
```

Второй (неполный) пример: `samples/product_2.json`.
Ошибочный пример, который сервис отклоняет до модели: `samples/product_3.json`.

## Примеры входных данных

Товары взяты из фида [СОЮЗ-ПРИБОР](https://www.souz-pribor.ru/yml/any/feed.xml).

1. `samples/product_1.json` — манометр **МП3-У** (Манотомь). Характеристики и описание собраны со страницы товара; это «полный» сценарий.
2. `samples/product_2.json` — модуль **МК110-224.8Д.4Р** (ОВЕН). Во фиде почти нет параметров, только артикул и тип — сценарий неполных данных.
3. `samples/product_3.json` — ошибочная выгрузка: пустое название, производитель числом, характеристики списком, описание `null`. Ответ `samples/result_3.json` — HTTP 422, модель не вызывается.

Готовые ответы для первых двух товаров лежат в `samples/result_1.md`, `samples/result_1.json`, `samples/result_2.md` и `samples/result_2.json`. Разбор ошибки — в `samples/result_3.md`.

## Промпт и решения

- System-промпт явно запрещает добавлять числа, классы точности, питание, ГОСТы и прочие факты не из входа.
- Ответ модели запрашивается как JSON.
- После ответа Python сверяет `key_specs` с входным `specs`: значения берутся из входа; новые характеристики удаляются; пустые помечаются «данных нет».
- Отдельно собирается список `missing_or_unclear` для контент-менеджера.
- SEO-заголовок обрезается до 70 символов; по длине описания 800–1200 добавляется предупреждение.

## Ограничения и возможные улучшения

- Нет базы данных, очереди и деплоя — только локальный прототип.
- Фид YML не парсится в рантайме: JSON готовится вручную.
- Длина SEO-описания не гарантируется одной генерацией (зависит от модели).
- Можно добавить повторную генерацию только SEO-текста, загрузку XML-оффера, сравнение моделей и кнопку «экспорт в CMS».
