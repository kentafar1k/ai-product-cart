# Черновик карточки товара КИПиА

Прототип на Python и FastAPI. По JSON или через веб-форму принимает данные прибора, отправляет их в LLM и возвращает черновик карточки для контент-менеджера: SEO-заголовок до 70 символов, SEO-описание на 800–1200 символов, характеристики, 3–5 поисковых запросов и commercial-блок.

Технические значения берутся только из входа. Если характеристики нет, в карточке стоит «данных нет», а в `missing_or_unclear` перечислено, чего не хватает. Ключ API лежит в `.env`, этот файл в `.gitignore`.

## Установка и запуск

Нужен Python 3.11+.

```powershell
py -3 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

В `.env` укажите ключ и модель. Подойдёт любой OpenAI-совместимый API. Примеры в `samples/` получены через Groq:

```
LLM_API_KEY=ваш-ключ
LLM_BASE_URL=https://api.groq.com/openai/v1
LLM_MODEL=openai/gpt-oss-120b
```

```powershell
uvicorn app.main:app --reload
```

Форма: http://127.0.0.1:8000

Запрос из файла:

```powershell
curl -X POST http://127.0.0.1:8000/generate -H "Content-Type: application/json" --data "@samples/product_1.json"
```

Ответ приходит и JSON, и Markdown. На странице оба блока можно скопировать. Пустые поля не останавливают генерацию. Некорректный JSON сервис отклоняет с кодом 422 и до модели не доходит. Ошибки API возвращаются текстом, без ключа и стектрейса.

## Примеры

Товары из фида [СОЮЗ-ПРИБОР](https://www.souz-pribor.ru/yml/any/feed.xml).

| Вход | Результат | Сценарий |
|---|---|---|
| `samples/product_1.json` | `result_1.md`, `result_1.json` | Манометр МП3-У, Манотомь: характеристики и описание есть |
| `samples/product_2.json` | `result_2.md`, `result_2.json` | Модуль МК110, ОВЕН: во входе почти нет параметров |
| `samples/product_3.json` | `result_3.md`, `result_3.json` | Пустое название и неверные типы полей, ответ 422 |

## Промпт и решения

Промпт в `app/prompts.py` запрещает добавлять диапазоны, классы точности, питание, ГОСТы и другие факты, которых нет во входе. Модель отвечает JSON.

После ответа код в `app/guardrails.py` заново собирает список характеристик из входного `specs`. Новые пункты удаляются, пустые получают пометку «данных нет». Заголовок обрезается до 70 символов. Если описание короче 800 или длиннее 1200 символов, в `warnings` остаётся пометка для контент-менеджера.

## Ограничения

Нет базы данных, админки и деплоя: это локальный прототип. Фид не разбирается при запуске, JSON для двух товаров подготовлен заранее. Длина SEO-описания зависит от модели и иногда требует правки по предупреждению.

Дальше можно перегенерировать только слишком короткое описание, принимать XML-оффер и выгружать черновик в CMS.
